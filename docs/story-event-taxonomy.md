# 전생록 스토리 사건 분류 체계

## 생성 순서

결과는 문장을 먼저 만들지 않는다. 먼저 한 명의 `Character Dossier`를 만들고, 그 설정에서 생애 연표와 여섯 장의 서사를 파생한다.

1. 판정 결과로 시대·지역·계층·직업의 경계를 정한다.
2. 허구의 이름·성별·외모·말투와 성격을 만든다.
3. 부모의 생존과 부재, 실제 양육자, 형제·또래, 집의 경제 상태와 교육·건강·이주 경험을 정한다.
4. 어린 시절의 상처가 핵심 두려움, 방어 습관, 콤플렉스와 평생의 고민으로 이어지게 한다.
5. 취미·재능·약점·좋아한 장소와 음식·생활 습관·신념·꿈을 정한다.
6. 양육자, 형제·또래, 핵심 인연, 스승·라이벌, 돌봄을 받은 사람으로 관계망을 만든다.
7. 탄생부터 죽음까지 나이순 이정표를 만들고, 그 뒤에만 여섯 장의 문장을 생성한다.

이름과 성별을 포함한 인물 정보는 사용자의 실제 정체성을 추론한 값이 아닌 창작 설정이다.

## 세분화 영역

| 영역 | 저장하는 세부 항목 |
|---|---|
| 정체성 | 허구 이름, 성별, 외모, 말투, 기질, 사회적 가면, 압박 반응, 콤플렉스 |
| 출생·가족 | 부모의 상태, 실제 양육자, 형제·또래, 혈연 밖의 가족, 경제 상태, 주거 |
| 성장 조건 | 교육, 건강과 신체 제약, 이주·피란, 어린 시절 물건과 사건 |
| 내면 | 형성 상처, 핵심 두려움, 방어 습관, 평생의 고민, 가장 큰 아픔, 숨은 바람 |
| 일상 | 직업의 의미, 취미, 재능, 약점, 좋아한 장소·음식, 생활 습관, 신념 |
| 욕망 | 겉으로 이루려는 목표, 실제 필요한 것, 잘못된 믿음, 내적 모순, 깨달음 |
| 관계망 | 양육자, 형제·또래, 사랑·동료, 스승·라이벌, 제자·돌봄 대상과 관계 변화 |
| 생애 연표 | 탄생, 유년기, 청년기, 삶의 전환기, 끝자락, 죽음의 나이와 결과 |
| 죽음 | 자연사, 질병, 사고, 재난, 충돌, 희생, 박해, 자발적 죽음, 실종과 이후 영향 |
| 유산·현생 | 남긴 규칙·사람·기술, 미완성된 꿈, 반복될 수 있는 감정과 행동의 잔상 |

## 목적

결과 문장을 추상적인 성향 설명으로 끝내지 않고, 사용자가 장면을 떠올릴 수 있는 사건 중심 이야기로 만든다. 하나의 결과는 `시대·지역의 큰 사건`, `관계에서 생긴 사건`, `직업 행동`, `선택의 대가`, `시간이 지난 뒤의 결과`, `마지막 기억`을 한 줄기로 연결한다.

## 사건 카테고리

| 카테고리 | 현재 사건 유형 | 이야기에서 맡는 역할 |
|---|---|---|
| 관계 | 만남, 사랑, 이별, 갈등, 라이벌, 화해, 스승·제자, 역할 역전 | 누구와 함께 선택했고 관계가 어떻게 달라졌는지 보여 준다. |
| 일과 생계 | 실수, 발견, 의뢰, 기술 충돌, 유산 | 직업이 단순한 라벨이 아니라 실제 행동과 손실로 드러나게 한다. |
| 공동체 | 재난, 부족, 이주, 축제, 권력 변화, 공동 결정 | 개인의 선택이 주변 사람들의 생활에 미친 영향을 만든다. |
| 여정 | 출발, 길 잃음, 구조, 귀환, 탐험 | 장소 이동, 위험, 발견과 귀환의 흐름을 만든다. |
| 내면 | 약속, 비밀, 후회, 도덕적 선택, 속죄 | 사건 이후 남은 감정과 현생 해석을 연결한다. |

코드의 기준 목록은 `apps/api/src/providers/story-event-catalog.ts`의 `STORY_EVENT_TAXONOMY`가 단일 원본이다.

## 현재 관계 사건 적용 방식

관계 판정별로 두 개의 구체적인 사건 후보를 두고, `answerHash`, `recordNo`, `relationshipId`를 사용해 항상 같은 후보를 선택한다.

| 관계 판정 | 사건 후보 |
|---|---|
| 오랜 동료 | 경쟁 끝에 드러난 신뢰 / 낯선 만남이 동료가 된 날 |
| 끝까지 지키려 한 가족 | 가족과 맞선 선택 / 오래된 서운함 뒤의 화해 |
| 다시 만나지 못한 사랑 | 말보다 행동으로 남은 사랑 / 떠나기 전 마지막 선택 |
| 배움을 이어받은 제자 | 가르침을 행동으로 옮긴 제자 / 제자가 스승을 멈춰 세운 순간 |

각 관계 사건은 다음 세 부분을 반드시 가진다.

1. `setup`: 사건 전 두 사람의 관계와 미해결 감정
2. `otherAction`: 위기 속에서 상대가 실제로 한 행동
3. `aftermath`: 사건 뒤 관계가 달라진 방식

## 이야기 조합 순서

1. 점수 결과에서 시대, 지역, 직업, 성격, 관계, 시대 사건, 마지막 기억을 확정한다.
2. 지역에 맞는 시간·장소·도구·큰 사건·즉각적인 대가·측정 가능한 결과를 가져온다.
3. 관계 판정과 결과 해시로 관계 사건 하나를 결정한다.
4. 직업 행동과 성격을 이용해 주인공이 무엇을 먼저 선택했는지 설명한다.
5. 지역 사건과 관계 사건을 같은 하루에 일어난 하나의 일화로 결합한다.
6. 마지막 기억에서 당시의 물건과 관계를 다시 불러온다.
7. 현자 화자가 사건의 의미를 현생 성향과 연결하되 실제 전생이라고 단정하지 않는다.

현재 조합만으로도 `8개 지역 사건 × 관계 사건 후보 8개 × 성격 4개 × 마지막 기억 6개`의 변주가 가능하며, 직업과 판정값에 따라 문장 세부가 더 달라진다.

## 사건 작성 원칙

- “큰 위기가 있었다” 대신 시간, 장소, 손에 든 물건을 쓴다.
- 상대의 감정을 설명하기보다 상대가 한 행동을 보여 준다.
- 선택에는 잃은 물건, 수입, 시간, 기회처럼 즉각적인 대가가 있어야 한다.
- 결과에는 며칠 뒤, 몇 명, 몇 가구처럼 확인 가능한 변화가 있어야 한다.
- 선행과 성공만 반복하지 않는다. 갈등, 오판, 후회, 화해, 역할 역전도 사용한다.
- 성별, 실존 인물, 실제 역사적 정체성을 임의로 부여하지 않는다.
- 폭력을 자극적으로 묘사하지 않고 생활의 붕괴와 회복에 초점을 둔다.
- 현자 화자는 몰입을 돕는 이야기 안내자이며 초자연적 사실을 보증하지 않는다.

## 새로운 사건을 추가할 때

1. `STORY_EVENT_TAXONOMY`에 재사용 가능한 유형인지 확인한다.
2. 기존 유형이면 해당 후보 배열에 `setup`, `otherAction`, `aftermath`를 추가한다.
3. 새 유형이면 분류 체계와 이 문서를 함께 갱신한다.
4. 기존 장소 사건과 결합했을 때 특정 시대·도구를 잘못 전제하지 않는지 확인한다.
5. 같은 입력의 결과가 변하지 않는 결정성 테스트와, 실제 서사에 세 부분이 모두 들어가는 통합 테스트를 추가한다.
