# 3.0 결과 분포 점검 (2026-10-28)

## 범위와 방법

- 코드: `packages/content/src/index.ts`의 질문 선택, `packages/scoring/src/result.ts`의 이야기 선택.
- 4,096개의 가상 첫 세션에서 각 단계의 질문을 현재 선택 함수로 고르고, 여섯 보기 중 하나를 균등하게 선택했다. 세션 시드는 실제 API와 같은 32자리 16진수 형식으로 만들었다. 동일한 입력으로 재실행할 수 있도록 `scripts/audit-story-selection.ts`에 표본 생성 규칙을 남겼다.
- 실제 사용자의 답변 데이터는 사용하지 않았다. 아래 수치는 실서비스 발생률이 아니라 **균등한 보기 선택을 가정한 시뮬레이션**이다. 점검 명령: `node scripts/tsx-cli.mjs scripts/audit-story-selection.ts`.

## 확인된 사실

1. 단계별 질문 4개는 각각 1,001~1,039회 선택되었다. 하지만 6단계 전체 질문 경로는 가능한 4,096개 중 **4개만** 나왔다. 질문 선택 해시의 낮은 비트를 단계별로 `% 4`에 사용해 단계 간 선택이 묶이는 구조다. API는 세션 생성 시 임의 시드를 쓰지만, 새 세션의 첫 질문 선택에는 동일한 결합이 적용된다. 최근 질문을 제외하는 재방문 경로는 이 표본에 포함하지 않았다.
2. 일반 이야기 119편은 모두 적어도 한 번 선택되었다. 균등 분포라면 편당 약 34회인데, 실제 범위는 **14~123회**였다. 희귀 이야기 1편은 18회(0.44%) 나왔다. 특정 이야기의 노출이 다른 이야기보다 훨씬 높은 것은 사실이지만, 균등 노출이 제품 목표인지부터 정해야 '불공정'이라고 판정할 수 있다.
3. 선택지 신호는 `notice` 4,053번, `connect` 4,087번, `release` 1,460번, `repair` 1,891번 나왔다. 이야기 카드에도 `notice` 110편, `connect` 91편, `speak` 90편이 있는 반면 `rest`는 6편, `explore`는 8편이다. 질문에서 보이는 신호와 이야기 카드의 구성이 균등하지 않다.
4. 같은 질문에서 답 하나를 다음 보기로 바꾼 3,072개 쌍 중 2,961개(96.4%)에서 **이야기 자체가 바뀌었다**. 답이 결과에 반영되는 것은 확인됐지만, 작은 선택 변화에도 결과가 크게 바뀌는 민감도가 있다.
5. 모든 질문에서 첫 보기만 고른 가상 사용자에게는 4종, 마지막 보기만 고른 사용자에게는 3종의 이야기만 나왔다. 이는 질문 경로가 4개뿐이고 답변 조합이 동일하면 결과 해시도 동일하기 때문이다. 실제 사용자의 위치 선호 정도는 아직 알 수 없다.

## 판단과 다음 변경안

현재 로직을 **편향이 없다고 말할 수 없다**. 질문 간 해시 상관관계는 명확한 다양성 결함이다. 우선 질문 선택에서 단계별 독립적인 해시 값을 사용해 질문 경로를 넓히고, 기존에 저장한 세션의 잠긴 질문은 유지해야 한다. 그다음 보기 순서 영향, 신호별 도달 가능성, 이야기 빈도를 실제 목표치와 비교하는 회귀 검사를 추가한다.

이 작업은 질문 배정과 결과 분포를 바꾸므로 기존 결과 산정 로직 변경에 해당한다. 이 문서는 진단이며, 채점식이나 120편 원고는 변경하지 않았다.
