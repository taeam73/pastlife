**재개 기록:** 사용자가 재개를 요청해 자동 작업 `120`을 다시 `ACTIVE`로 바꿨다. 이 문서 아래의 52/120 수치는 재부팅 직전 기록이며 현재는 87번 에스더·88번 마리아·89번 하피즈·90번 누라·91번 카림·92번 나야를 추가해 **마지막 기술 등록 58/120**이다. 최신 수치와 보류 사항은 `PROJECT_STATUS.md` 및 `docs/final-moment-variety-audit.md` 맨 위를 따른다.

사용자 요청에 따라 작업을 일시중지했다. 자동 작업 `120`도 `PAUSED`로 바꿨다. 사용자가 재개를 요청하기 전에는 추가 편집을 하지 않는다. 커밋·푸시·배포하지 않았고 기존 미커밋 변경은 그대로 둔다.

- 가장 최근 완성한 기술 등록은 85번 타비 v2와 86번 할릴이다. 타비 v2는 원고·03·설정·앱 그림 URI·삽화를 맞췄고, 52건 등록 검사와 콘텐츠/타입/API 검사를 통과했다. 자세한 보류 사항은 `docs/final-moment-variety-audit.md` 맨 위와 `docs/life-deep-audit-second-pot-of-sorghum.md`를 본다.

## 재개 순서

1. 필수 기준·계획·검수표·`PROJECT_STATUS.md`와 실제 Git 변경을 먼저 읽는다. 특히 87번 설정만 먼저 적혀 있음을 확인하고 중복 작업을 피한다.
2. 87~92번의 기존 01~04·설정·관계·연령을 다시 대조하고 마지막 장면의 증상·원인·구도·사후 반응이 서로 다른지 묶음으로 설계한다. 87번은 초안을 확정한 뒤 마지막 본문·03·고유 삽화·앱 매핑을 묶어서 반영한다.
3. 묶음별 콘텐츠·타입·API·그림 매핑 검사를 한다. 작품별 낭독·역사 사실과 창작의 구분·유사 장면 비교를 생략하지 않는다. 승인 수는 실제 검수 전까지 올리지 않는다.
4. 마지막 단계에서만 최종 데이터로 전편 PDF·공유 이미지를 일괄 생성·열어 검수한다.

재부팅 전 로컬 개발 서버는 API `localhost:4001`, Expo 웹 `localhost:8282`에서 실행 중이었다. 재부팅하면 다시 실행해야 한다. 사용자 브라우저에는 `http://localhost:8282/result` 탭이 열려 있었다. 에이전트가 앱 화면을 직접 여는 자동화 요청은 보안 승인 단계에서 거절됐으므로 우회 시도 없이 사용자에게 직접 화면 확인을 맡긴다.
