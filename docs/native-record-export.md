# 3.0 휴대폰 저장·공유 연결 및 검증 한계

2026-10-24 기준. 이 문서는 **연결된 코드**와 **실제 기기 검증**을 분리해 기록한다.

## 구현

- Expo SDK 57에 맞는 `expo-print`, `expo-sharing`, `expo-asset`, `expo-file-system`을 모바일 패키지에 직접 연결했다. Android/iOS 파일 공유는 [Expo Sharing](https://docs.expo.dev/versions/v57.0.0/sdk/sharing/), HTML PDF 생성은 [Expo Print](https://docs.expo.dev/versions/v57.0.0/sdk/print/) 문서를 기준으로 했다.
- 3.0 결과에서 마지막 순간 읽음 표시가 켜져야 `이미지 공유`와 `전생기록 다운로드`가 활성화된다. 2.5 경로는 기존 방식으로 남겼다.
- 휴대폰 PDF는 표지에 배경·인물·전생록 로고·프로필을 합치고, 01~04, 마지막 순간 삽화·원고, 전생록 맺음말을 HTML A4 페이지로 만든다. 번들 그림은 로컬 파일을 base64로 포함해 iOS 인쇄 WebView의 로컬 그림 제한을 피한다. `expo-print`로 기기 캐시에 PDF를 생성하고 시스템 공유창에서 사용자가 파일 저장 위치를 선택하도록 한다.
- 휴대폰 공유 PNG는 화면 밖의 01 프로필 카드가 배경·인물·로고 그림을 모두 불러온 뒤 `react-native-view-shot`으로 캡처하고 시스템 공유창을 연다. 이미지가 준비되지 않으면 빈 카드가 전송되지 않도록 오류로 처리한다.
- 웹은 기존 Canvas PDF와 공유 PNG 다운로드 경로를 유지한다. 휴대폰에서 공유창을 열었다는 상태를 실제 파일 저장 완료라고 표현하지 않도록 안내 문구를 나눴다.

## 확인한 범위

- 모바일 TypeScript 검사와 기존 모바일 단위 검사 12건이 통과했다.
- 인메모리 API에서 라비 결과를 실제 여섯 답변으로 다시 뽑았다. 320px 결과의 두 번째 테스트 광고→마지막 순간→읽음→웹 PDF·PNG 다운로드와 768px 마지막 화면을 재검사했다. 가로 넘침·브라우저 오류는 없었다.
- 이 환경에는 연결된 Android/iOS 기기가 없어 **네이티브 PDF 렌더링, 공유창, 파일 앱 저장, PNG 캡처의 실제 해상도**는 확인하지 못했다. iOS와 Android 각각에서 파일을 열고 01~04·마지막 순간·이미지의 내용과 글꼴·쪽 나눔을 눈으로 확인해야 한다. 이 검증 전에는 120편 중 어느 편도 전체 경험 완료로 세지 않는다.
