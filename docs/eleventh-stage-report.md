# 전생록 11단계 구현 보고서

PRD 2.5의 핵심 사용자 퍼널을 측정하는 개인정보 제한형 분석 이벤트 계층을 구현했다.

## 구현

- 23개 PRD 이벤트 이름을 공용 Zod 계약으로 제한
- 세션·결과·질문·선택지 ID, 버전, 상태, locale, 플랫폼, 보기/공유 형식만 허용
- 답변 원문, 질문 문구, 이메일, 표시 이름, 임의 자유 텍스트 거부
- `POST /api/v1/analytics/events` 수집 API
- Prisma append-only `analytics_events` 테이블과 조회용 인덱스
- 로컬/E2E용 최대 10,000건 메모리 버퍼
- 모바일의 세션 시작, 질문 노출/응답, 광고, 결과, 이미지, 보기 모드, 해금, 공유, 로그인, 아카이브, 재탐색 계측
- 분석 서버 오류나 오프라인 상태가 사용자 흐름을 막지 않는 best-effort 전송

## 개인정보 경계

서버는 strict schema를 사용한다. 정의되지 않은 이벤트와 메타데이터 필드는 HTTP 400으로 거부한다. 따라서 클라이언트가 실수로 `answerText`, 이메일 또는 임의 설명을 보내도 저장되지 않는다. 운영 보존 기간과 삭제 정책은 배포 전 개인정보 정책에 맞춰 정해야 한다.

## 다음 단계

다음 단계는 실제 스테이징 PostgreSQL에 2.5 마이그레이션을 적용하고, 분석 데이터를 읽는 운영 대시보드 또는 외부 분석 싱크를 연결하는 것이다. 이후 MP4 렌더 워커와 라이선스 음원을 연결하면 배포 후보 빌드 단계로 넘어갈 수 있다.
